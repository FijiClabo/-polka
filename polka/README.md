# Полка — дочитай книгу за 30 дней

Telegram-бот и мини-приложение по брифам `01_polka_project.md` и `03_polka_dev_brief.md` и макетам «Полка · v3».
Пользователь добавляет свою книгу (epub/fb2 или бумажную), получает план на 21–60 дней, каждый день читает
отрезок и за минуту пересказывает его ИИ голосом или текстом. Стрик, заморозки, напарник с общим стриком,
друзья, ачивки, полка с конспектом и карточки для сторис.

> Название не зашито в код: `PROJECT_NAME` в `.env` (Полка / Дочитал / Закладка / Вслух).

## Что сделано

**Бот** (aiogram 3)
- Онбординг: 3 коротких сообщения → часовой пояс (кнопки Калининград…Камчатка, «другой» или геопозиция) →
  время утреннего отрезка и вечернего напоминания → **пробный пересказ** на отрывке из Чехова (общественное
  достояние) → добавление книги → статус («ты в списке» / «ожидаем оплату»).
- Книга файлом прямо в чат: epub, fb2, fb2.zip до 20 МБ. Разбор в фоне, план можно выбрать **кнопками в чате**
  или в мини-приложении. Бумажная книга — диалогом (название, автор, страницы).
- Ежедневный цикл: утром отрезок, вечером одно напоминание (если день не сдан), уведомление напарнику.
  Не больше 3 сообщений по инициативе бота в день, толчки от друзей и напарника — не больше 2.
- Пересказ: любой текст длиннее 50 знаков или голосовое (до 3 минут, «Я услышал: …»). Вердикты
  «засчитано / уточни / не похоже», до двух уточнений, ответ на уточнение — любой длины.
- Пары (`/pair` — ссылка-приглашение), друзья (`/friends` — личная ссылка, толчки), ачивки (9 штук),
  финиш с карточкой, `/settings`, `/book`, `/today`, `/help`, `/delete_me`.
- Админ-команды ведущего (см. ниже), экспорт CSV с готовыми метриками теста.

**Мини-приложение** (React + TypeScript, официальный SDK Telegram) — по макетам v3, тёмная и светлая темы:
Сегодня · Чтение отрезка (размер шрифта, интервал, запоминает место) · Пересказ голосом/текстом прямо в
приложении · Забег (календарь дней, карточка дня с пересказом и ответом ИИ) · Друзья и напарник · Карточка друга ·
Полка · Конспект · Финиш (конфетти, «+1» на полке, «Поделиться» в сторис или картинкой в чат) · Профиль
(настройки, значки, FAQ) · Добавление книги и выбор срока · Приветственные экраны. У каждого экрана есть
состояния загрузки, пустоты и ошибки. Нативные кнопки Telegram «Назад» и «Настройки», тактильный отклик.

**Правила** (`/core`, покрыто тестами): день 04:00–04:00 в поясе пользователя, «догнать вчерашний», один отрезок
в день (два — в последние 3 дня и в дни отсрочки), заморозка 1 в неделю без накопления, общий стрик пары,
финиш с отсрочкой 3 дня, «та же книга», доступ к пересказам напарника по доле книги, лимиты толчков.

**Книги** (`/books`): безопасный разбор (защита от XML- и zip-бомб, без внешних сущностей), оглавление nav/ncx,
главы по якорям внутри одного файла, отбрасывание обложки/оглавления/выходных данных/рекламы/«об авторе»/сносок,
распознавание DRM и сканов, условные страницы по 1800 знаков, разбивка на отрезки по границам глав (±40%),
длинные главы — «Глава 4 (часть 2 из 3)», без глав — «День 1, День 2…». Варианты срока по правилам 9.4.

**ИИ** (`/ai`): адаптеры `LLMProvider` (Claude основной, YandexGPT запасной, автоматическое переключение) и
`STTProvider` (Yandex SpeechKit, Whisper-совместимый API). Строгий JSON, повтор при невалидном ответе,
при сбое — «засчитано без сверки»; если оба ИИ недоступны — «принял, проверю чуть позже», день не сгорает.
Краткие содержания отрезков в фоне дешёвой моделью. Набор из 29 пересказов для проверки качества.

**Надёжность**: всё идемпотентно — перезапуск или простой сервера ничего не ломает, пропущенные дни
закрываются при следующем проходе. Голосовые не хранятся. Исходный файл книги удаляется после разбора.
Текст книги отдаётся только владельцу; друзья не видят пересказов и конспектов (это проверено тестами).

**Тесты**: 143 автотеста — правила, ачивки, часовые пояса, разбор 10 типов файлов, сценарии забега
на SQLite и PostgreSQL, приватность API, сквозной прогон бота (онбординг → книга → план → оплата →
пересказ → админ-команды).

### Что я добавил сверх ТЗ (и почему)

| Добавлено | Зачем |
|---|---|
| Пересказ голосом и текстом **внутри мини-приложения** (как на макете «Пересказ голосом»), с запасным путём «отправь голосовое в чат» | По ТЗ кнопка возвращала в чат, но на макете запись в приложении — так меньше шагов |
| Выбор срока **кнопками прямо в чате** после разбора файла | Не нужно открывать приложение ради одного нажатия |
| Загрузка файла книги **из мини-приложения** | Удобнее на компьютере |
| Вопрос-приглашение к пересказу для каждого отрезка («Что произошло на сеансе в Варьете?») | Как на макете; готовится вместе с кратким содержанием |
| Бесплатный спринт предлагается и тогда, когда открытого забега нет | Иначе новичку нечего делать в боте |
| Карточки для сторис в двух размерах + «Поделиться в сторис» через Telegram | Основной канал роста |
| Самодиагностика `scripts/doctor.py` | Сразу видно, какой ключ не работает и как это исправить |
| Демо-режим (`scripts/demo_seed.py`, `LLM_PROVIDERS=demo`) | Посмотреть приложение без ключей и без Telegram |
| `/user @name` для ведущего | Чтобы найти id пересказа для `/override` без доступа к базе |
| Нейтральные формулировки без «сдал(а)» | Telegram не сообщает пол; «Аня: день сдан» звучит естественно |

## Запуск на сервере — по шагам

```bash
# 1. Зайти на сервер
ssh root@IP_СЕРВЕРА

# 2. Забрать код (для приватного репозитория GitHub попросит логин и токен — Settings → Developer settings → Tokens)
git clone https://github.com/FijiClabo/-polka.git polka-repo
cd polka-repo/polka

# 3. Установить Docker, файрвол, ежедневный бэкап (один раз)
sudo bash scripts/server_setup.sh

# 4. Заполнить настройки (Ctrl+O — сохранить, Ctrl+X — выйти)
nano .env

# 5. Запустить. Скрипт соберёт всё, поднимет HTTPS и проверит настройки
bash scripts/deploy.sh
```

В конце `deploy.sh` запускает самодиагностику: ✅ — всё хорошо, ❌ — что исправить и как.
HTTPS-сертификат Caddy получает сам (порты 80 и 443 должны быть открыты, домен — смотреть на сервер).

Проверка: открой бота в Telegram → `/start`. Кнопка «Полка» внизу чата открывает мини-приложение.

## Настройка бота в BotFather

1. `/newbot` → имя (например, «Полка — дочитай книгу») и username → получишь **токен**.
2. `/setuserpic` — аватар бота.
3. `/setdescription` и `/setabouttext` — бот сам ставит короткое описание, но можно своё.
4. **Мини-приложение** — кнопку «Полка» в меню чата бот настраивает сам при запуске.
   Чтобы была красивая ссылка `t.me/<бот>/app` и кнопка «Открыть» в профиле бота:
   `/mybots` → бот → **Bot Settings → Configure Mini App → Enable Mini App** → URL: `https://ТВОЙ_ДОМЕН/app/`.
5. Команды (`/today`, `/pair` …) бот регистрирует сам; админам видны дополнительные.

## Ключи ИИ и распознавания речи

**Claude (основной ИИ)** — [console.anthropic.com](https://console.anthropic.com) → Billing (пополнить) → API Keys →
Create Key → `ANTHROPIC_API_KEY`. Модели заданы в `.env`: `claude-opus-5-5` для проверки пересказов (с
`ANTHROPIC_EFFORT=low` — быстро и недорого) и `claude-haiku-4-5` для кратких содержаний. Оценка расхода: проверка
одного пересказа ≈ 8 тыс. токенов на входе ≈ $0,04; забег на 30 человек × 30 дней ≈ $40–60 вместе с уточнениями.
Хочешь дешевле — `ANTHROPIC_MODEL=claude-sonnet-5-5` (примерно вдвое), но сначала прогони набор `ai_eval`.

**YandexGPT и SpeechKit** (запасной ИИ и голос) — [console.yandex.cloud](https://console.yandex.cloud):
1. Создать платёжный аккаунт и каталог; **ID каталога** → `YANDEX_FOLDER_ID`.
2. «Сервисные аккаунты» → создать с ролями `ai.languageModels.user` и `ai.speechkit-stt.user`.
3. В аккаунте → «Создать новый ключ» → **API-ключ** → `YANDEX_API_KEY`.

**Whisper вместо SpeechKit** (необязательно): `STT_PROVIDER=whisper`, `WHISPER_API_URL`, `WHISPER_API_KEY`
(подходит любой Whisper-совместимый сервис).

**Проверка качества ИИ** до запуска (раздел 7.5 ТЗ): `docker compose exec app python -m scripts.ai_eval` —
прогоняет 29 пересказов (честные, короткие, выдуманные) через каждую модель и показывает долю ошибочных
отказов честным читателям (цель — меньше 5%). Добавляй в `tests/ai_eval/dataset.json` реальные пересказы.

## Как провести забег (ведущему)

Все команды — в личке с ботом, только для `ADMIN_TG_IDS`. Подсказка: `/admin`.

| Команда | Что делает |
|---|---|
| `/run_new Осенний забег \| 2026-10-20 \| 990` | Создать забег (название, дата старта, цена). Новые пользователи записываются в него автоматически |
| `/run_date 2026-10-20` | Перенести дату старта |
| `/run_info` | Сводка по забегу |
| `/grant @username` или `/grant 123456789` | Отметить оплату → участник получает «Ты в списке» |
| `/refund @username` | Возврат, рассылки отключаются |
| `/pairs_auto` | Случайно разбить **половину** оплативших без пары на пары (вторая половина — контрольная группа) |
| `/pair_set @a @b` | Назначить пару вручную |
| `/user @username` | Статус участника и последние пересказы с id |
| `/override 123 accepted` | Засчитать ошибочно отклонённый пересказ, стрик пересчитывается |
| `/stats` | Сдали сегодня, средний стрик, выбывшие, доля отказов ИИ |
| `/broadcast текст` | Сообщение всем участникам |
| `/export` | ZIP с CSV (участники, пересказы, дни, события) и `metrics.txt` — 4 метрики теста отдельно для пар и одиночек |

**Типичный сценарий:** `/run_new` → раздать ссылку на бота → люди проходят онбординг, добавляют книги →
переводят оплату → ты делаешь `/grant` → накануне старта `/pairs_auto` → в день старта утром всем приходит
первый отрезок. Дальше бот работает сам; ты смотришь `/stats` и при жалобах — `/user` и `/override`.

## Тестовый прогон на 3–5 знакомых

Чтобы прожить «забег» за час, а не за месяц, в `.env`:
```
FAST_DAY_MINUTES=20     # «сутки» = 20 минут
ALLOW_TIMEWARP=true     # команда /timewarp 24 — перемотать часы бота на сутки вперёд
```
Перезапусти (`bash scripts/deploy.sh`), создай забег с датой «сегодня», пройди 3 «дня» с двух аккаунтов в паре.
Синтетические книги для проверки: `docker compose exec app python -m scripts.make_samples /app/data/samples`
(или локально в `./samples`). **Перед настоящим забегом верни `FAST_DAY_MINUTES=0` и `ALLOW_TIMEWARP=false`**
и пересоздай базу, чтобы тестовые данные не попали в метрики:
`docker compose down -v && bash scripts/deploy.sh` (удаляет базу!).

Проверить свои реальные файлы книг: положи их в `tests/books/files/` и запусти
`python -m scripts.check_book tests/books/files/*` — для каждого будет результат или понятная причина отказа.

## Локальный просмотр и разработка

Посмотреть приложение на своём компьютере без Telegram и без ключей (нужны Docker, Python 3.12, Node 22):
```bash
cd polka
docker run -d --name polka-dev-db -p 5432:5432 -e POSTGRES_USER=polka -e POSTGRES_PASSWORD=polka -e POSTGRES_DB=polka postgres:16-alpine
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements-dev.txt
alembic upgrade head && python -m scripts.demo_seed          # демо-забег, день 12 из 30
DEV_AUTH_BYPASS=true LLM_PROVIDERS=demo BOT_TOKEN= python main.py
# в другом окне:
cd webapp && npm install && VITE_DEV_TG_ID=1001 npm run dev  # → http://localhost:5173/app/
```
`DEV_AUTH_BYPASS` отключает проверку подписи Telegram — **никогда не включай его на сервере**.
С ботом локально: `bash scripts/dev.sh` (режим polling; мини-приложение в Telegram откроется только по HTTPS).

Тесты и проверки:
```bash
pytest                       # 143 теста (SQLite); на PostgreSQL: TEST_DATABASE_URL=postgresql+asyncpg://... pytest
ruff check .
cd webapp && npm run build   # проверка типов TypeScript + сборка
```

## Устройство проекта

```
polka/
  core/        правила: день, стрик, заморозки, пары, финиш, ачивки — без Telegram и базы, с тестами
  books/       разбор epub/fb2, разбивка на отрезки, варианты срока, генератор тестовых книг
  ai/          LLMProvider (Claude, YandexGPT, demo), STTProvider (SpeechKit, Whisper), промпты, разбор вердикта
  services/    сценарии поверх базы: сдача пересказа, закрытие дня, пары, друзья, полка, экспорт
  bot/         обработчики aiogram (онбординг, книги, день, друзья, админ), кнопки и рассылка
  api/         FastAPI для мини-приложения, проверка initData
  jobs/        планировщик: утро, вечер, закрытие дня в 04:00, очередь отложенных проверок, краткие содержания
  share/       карточки для шеринга (Pillow) + шрифты (OFL)
  db/          модели SQLAlchemy 2 и миграции Alembic
  webapp/      мини-приложение React + TypeScript + Vite
  tests/       автотесты, набор для проверки ИИ (ai_eval), ожидания по книгам (books/expected.md)
  scripts/     развёртывание, бэкапы, самодиагностика, демо, проверка книг и ИИ
  texts.py     все тексты бота в одном месте — правь тон здесь
  main.py      точка входа: API + бот + планировщик в одном процессе
```

Схема работы на сервере: **Caddy** (HTTPS, сжатие) → **app** (FastAPI: `/api/*`, `/app/*` — мини-приложение,
`/tg/webhook` — Telegram; внутри же бот и планировщик) → **PostgreSQL**. Всё в `docker-compose.yml`.

## Важно до публичного запуска

Это из раздела 12 общего документа — код к этому готов, но нужны решения вне кода:
- **Название**: «Полка» занято известным проектом — проверь товарный знак. Смена — одна строка `PROJECT_NAME`.
- **Тексты книг**: схема «пользователь загружает свой файл, текст видит только он» реализована строго
  (тесты это проверяют) — но её стоит показать юристу.
